## Outcome

IC3 accelerates the authoritative listing-discovery stage after IC2 first value while preserving complete-scan authority and PB9 Last Known Good behavior.

The production path now supports:

```text
provider listing
-> bounded shared request budget
-> trustworthy terminal-page discovery when available
-> bounded page fan-out
-> progressive complete:false construction batches
-> full authoritative scan only after every required page succeeds
```

For Yupoo category routes, the Provider Engine uses the lighter gallery route while preserving the same source identity and normalized evidence contract. If trustworthy terminal-page evidence is unavailable, the scanner retains the conservative sequential natural-end path rather than guessing completion.

Progressive construction work is deliberately capped at the first **48 unique private listing products**. Later pages continue through the full authoritative scan without paying repeated construction-preview normalization/write cost.

## Implementation chain

- **#291 — IC3 production A/B proof**: added a real baseline-vs-current proof using the same large catalog and exact identity/taxonomy comparison;

PR **#294** separately approved the IC4–IC6 SLO60 governance/decomposition. It did not alter IC3 production behavior.

## Defects and performance findings resolved during proof

IC3 production work exposed two important findings rather than hiding them:

1. the first real A/B after page fan-out improved the large-catalog scan by only ~1.3%, below the required 5% threshold;
2. page fan-out alone reduced page work but did not sufficiently reduce end-to-end listing latency.

The response was not to lower the threshold. The Provider Engine path was optimized to use the lighter category gallery route, the proof was aligned with the exact production Provider Engine entrypoint, and safe request/concurrency telemetry was added.

The final proof then achieved **9.2%** while preserving product identity/taxonomy and the same maximum upstream concurrency of 4.

IC3 also found that continuing construction-preview normalization after its bounded useful capacity would add cost without customer value. PR #293 stops that optional work after 48 unique products while the authoritative listing scan continues to completion.
