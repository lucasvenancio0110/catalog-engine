## Root cause now quantified

The most important baseline finding is that most customer waiting time is architectural, not UI rendering time.

Before any IC2 acceleration:

- more than **35 minutes** elapsed before the normal initial import started;
- the normal import candidate path waits for isolated tenant data-plane/runtime readiness and cron-owned dispatch prerequisites;
- the scheduler is recovery-safe but not suitable as the first-value latency boundary;
- verified preview then waits for full detail import, CEI/classification, verification and runtime readiness.

This validates the IC architecture decision: first useful private value must use a separate safe construction path rather than weakening L2/PB9 verification.
