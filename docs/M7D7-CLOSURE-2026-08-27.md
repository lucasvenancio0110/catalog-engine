## Authority contract proven

Schema v7 establishes:

- `catalog_serving_authority` as the tenant-scoped canonical serving revision;
- `supplier_sync_stage_authority` as immutable run-scoped base-authority evidence;
- compare-and-swap protection against a stale base revision;
- one atomic canonical transaction for the admitted envelope;
- a final `promoted` stage state only when the serving-authority row identifies the exact run/source and has advanced exactly one revision;
- replay of the same already-promoted run as an idempotent success/no-op;
- rejection of a competing run based on stale authority.

Production canary evidence also proved that D7 did **not** advance control-plane cursor/schedule state. The control-plane job remained `finalizing/finalize` after canonical promotion.

## Safety envelope

The D7 primitive remains fail-closed and requires, before promotion:

- exact tenant/source/run identity;
- stage state `verified`;
- verification contract `sync_candidate_verified_v1`;
- `safety_outcome='proceed'`;
- no disqualifying error;
- current merchant-override provenance;
- no public source/private-state leak;
- no MISSING/REMOVED event in this slice;
- an unchanged authority base revision;
- the bounded transaction envelope documented by the architecture decision.

The production envelope remains capped at 20,000 composed products and 40,000 media relationships for this primitive.

## Closure decision

The next officially approved submilestone is:

**M7D8 — Verified Promotion and Cursor Commit**

Its mandatory order is:

```text
verified candidate
→ M7D7 atomic canonical authority transaction
→ promoted
→ D8 cursor / schedule / control metadata commit
```

The cursor, schedule and control-plane authority must never advance before the tenant serving-authority transaction durably commits. If the process dies after promotion but before control-plane finalization, replay must observe the exact run already `promoted`, must not promote it again, and must commit only the remaining control metadata exactly once.
