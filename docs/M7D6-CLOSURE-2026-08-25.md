## Production defect caught before closure

The first trusted-main deployment of the M7D6 implementation reached production successfully:

- application deploy run `32863235274` = **SUCCESS**;
- Queue consumer activation run `32863235296` = **SUCCESS**.

The first scheduler-owned candidate-verification canary, run `32863333346`, failed. The verifier required the read-only SQLite integrity check `PRAGMA foreign_key_check`, while the tenant internal D1 command intentionally accepts only SQL beginning with `SELECT`, `INSERT`, `UPDATE` or `DELETE`. The request therefore failed closed with `tenant_data_plane_sql_invalid` before D1 executed the check.

The failure did not justify widening the tenant SQL allowlist or weakening foreign-key verification. PR `#145` fixed the transport boundary by normalizing only the exact read-only foreign-key pragma to SQLite's equivalent table-valued form:

```sql
SELECT * FROM pragma_foreign_key_check
```

Regression coverage proves that the normalized statement passes the real tenant SQL normalizer and preserves the same finding-row semantics as `PRAGMA foreign_key_check`.
